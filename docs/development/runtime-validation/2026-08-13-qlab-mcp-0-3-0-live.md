## EDIT / MOVE / DELETE

All operations used exact UUIDs, a fresh dry-run, one execution, and fresh
readback. No output-producing property was touched.

- Edit: `MCP_MOVE_RUNTIME_A` (`33B90938-AF3B-4D82-8AB1-3179D34B562D`),
  `flagged=false -> true`, then rollback `true -> false`. Both real calls
  returned `updated_with_confirmed_timeouts`; after-read confirmed the value.
  The timeout was not retried.
- Create: one blank Memo after `MCP_MOVE_RUNTIME_C`
  (`10F0A61A-AA01-46C6-A2FC-B915C1E262D8`). QLab returned
  `BAFD381E-A8FD-4A0F-810F-A46BCBD0277E`, status `created`, parent
  `E15F837F-BA26-4362-965E-25B277A12B79`, index 14, healthy and inactive.
- Delete: the created UUID was deleted once with status
  `deleted_after_convergence`. Fresh detail read returned
  `cue_ref_unresolved`; the anchor and original sibling structure remained.
- Move: `MCP_MOVE_RUNTIME_A` moved after `MCP_MOVE_RUNTIME_B` with status
  `moved_after_convergence`, then rolled back before `MCP_MOVE_RUNTIME_B` with
  the same status. Final order was A, B, C and both parents remained exact.
- Negative gate: `cueTargetID` on the Memo was rejected in both dry-run and
  real mode with `preflight_failed`; `planned_operations=[]` and
  `executed_operations=[]`, so no setter was sent.
- Cross-tool workflow: a second temporary Memo was created after C, renamed to
  `MCP_RUNTIME_CROSS_EDIT`, moved after B, and deleted. Each step used a fresh
  dry-run/token and readback; the final name/UUID was absent and the original
  A-B-C order was restored.
- Sequential Create/Delete: two ordered Memos were created with the dedicated
  `confirm:createCues:v1` token; each item was verified before the next `/new`.
  Both exact UUIDs were then deleted with one reviewed sequential Delete plan
  and each disappearance was confirmed.
- Batch Edit: three temporary Memos received two safe properties each
  (`name`, `flagged`) in one call; all three readbacks matched. A batch with
  one invalid UUID was blocked before setters, as were invalid values and an
  empty update item. The three fixtures were restored and deleted.
- Cross-parent Move: a Memo moved from Group A to empty Group B at `position=
  first`, then back to Group A, with exact parent/index readback both times.
- Recursive Delete: a named root Group containing two Memos, a subgroup, and a
  nested Memo was emptied. Four descendants were deleted deepest-first and the
  root was preserved exactly as specified.
- Move invalidations: nonexistent source/destination, both placement fields,
  missing placement, and self-reference all returned `preflight_failed` with
  zero planned moves; A-B-C order stayed unchanged.
- Delete invalidations: nonexistent UUID, missing token, malformed token,
  invalid recursive/root combination, and a mixed valid/invalid batch all
  failed closed without deleting the valid fixture.

Fixtures created: all temporary leaf cues and descendants were deleted and
confirmed absent. Two empty Group containers remain because the public Delete
tool rejects container UUIDs (`Container cues and cues with children are
blocked; delete is leaf-only`). No GO, playback,
audition, stop, panic, `/live`, raw OSC, or direct AppleScript write was used.

query tools returned exact UUIDs, parent IDs, health, activity, and truncation

annotations, so protocol-level schema/annotation claims are intentionally not
made. Descriptions consistently required explicit workspace and cue UUIDs and
the readiness → dry-run → fresh token → execute once → fresh readback flow.
