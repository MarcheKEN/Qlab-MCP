# Playlist crossfade: QLab 5.5.10 investigation

Build 5510; no cue execution or physical output. The original workspace file
retained SHA-256 `acf48be9c237cda2e0298b1671009487df98a07d10439dba35e095795fc0cdb3`.
All writes below targeted temporary copies of that saved workspace.

For Group cue `22EDDB5C-3F86-4CCB-AF9D-FA75CA88ECFF`, the saved baseline
was duration 2.4, in/out durations 0.0288, and offset -0.0288 seconds. This
baseline was already asymmetric; it must not be interpreted as a default.

The AppleScript `playlist crossfade duration` setter changed 2.4 to 1.2; the
saved in/out durations and offset remained unchanged. After closing and
reopening the copy, AppleScript read 1.2 and the Playlist inspector showed
1.2 seconds and rounded in/out labels of 0.0 seconds. AppleScript therefore
does not reproduce the inspector's proportional update in this case.

In a separate throwaway copy, an experimental archive edit changed 1.2 to
2.0 and scaled both in/out durations from 0.0288 to 0.048 and offset from
-0.0288 to -0.048. Before QLab opened the file, the saved effect-graph check
passed and the other fields of the target cue and both fade objects retained
their original references. QLab opened the copy; the inspector showed 2.0.
After save, close, and reopen, the four edited values remained unchanged and
the decoded Playlist curve descriptions matched the initial descriptions.

QLab reserialized the archive during its save. The current index-sensitive
effect-graph comparison then returned false, so effects cannot be declared
preserved across that save from this test. A control copy opened and saved
without any cue edit also failed the same index-sensitive comparison. An
exploratory UID-independent traversal found the same per-cue effect graphs for
all 210 cue owners in both copies. That traversal did not compare patch effects
or sharing across different owners, so it is not a complete preservation proof.
One asymmetric sample also cannot
establish safety for custom curves, shared references, edge cases, or all
other workspace content. The OSC duration writer remains blocked.

## Custom-curve comparison

A second fixture was made in QLab: 3-second crossfade, custom fade-out with
three points, and S-Curve fade-in. Two copies started from that exact saved
state. In the first, the inspector changed the duration to 4.5 seconds. In
the other, an experimental archive mutation scaled both fade durations and
the offset by 1.5. After QLab saved, closed, and reopened each copy, both
reported duration 4.5, in/out durations 4.5 and offset -4.5 seconds. Their
decoded Playlist curves were identical, including all three custom points;
the reopened experimental copy's inspector showed 4.5 seconds and Custom
Curve. This validates one custom example only, not arbitrary curves or
effect preservation. No cue was executed.

An exploratory traversal of all 218 Audio/Mic cue effect owners preserved
the same object graph and cross-owner sharing in all three files, after
ignoring UID renumbering of scalar values and class descriptors. A separate
traversal anchored the six output patches and their 12 effect roots, plus
four template cue effect roots. It matched across all three files after
normalizing QLab-regenerated template cue identities by type and role.
The test workspace contains two archived `F53Effect` objects in the cue
archive and no such objects in the output patch archive. Thus this does not
validate unknown plug-ins, populated patch buses, extra template roles, or
arbitrary archive graphs. These exploratory traversals are not production
preservation checks and do not justify removing the existing fail-closed gate.

## Installed third-party effects

QLab was used to add SnapTune to Audio cue 334 and Graillon 3 to cue output
bus 1 of Patch 1, exclusively in another temporary copy. A separate experimental
archive edit changed the Playlist crossfade from 3 to 4.5 seconds. The existing
index-sensitive effect check passed on the generated bytes before opening.
After QLab opened, saved, closed and reopened the copy, the inspector still
showed both effects enabled. The exploratory UID-independent graphs matched
for all 218 Audio/Mic owners, all six output patches and four cue templates;
the curve description was unchanged and the duration/offset/fades were
4.5/-4.5/4.5/4.5 seconds. This is not evidence of audio processing, unknown
plug-in handling, or a production-quality graph comparison.

## Simulated missing plug-in

Another disposable fixture changed the Audio Unit component subtype of the
SnapTune effect on cue 334 to an uninstalled value while keeping its saved
state. QLab showed `SnapTune (missing)`. It preserved the simulated missing
effect graph on save and reopen. In a further copy, the same experimental
crossfade edit changed 3 to 4.5 seconds; after save, close, and reopen, the
missing-effect graph and the six patch effect graphs matched their baselines,
and the curve and expected timing values persisted. This covers one simulated
missing component, not arbitrary unknown classes or malformed plug-in states.

A bounded archive planner creates the same change with copy-on-write
Fade objects and checks saved effect graphs before returning generated bytes.
Its output for the missing-plug-in fixture was saved, closed and reopened in
QLab; the expected 4.5-second summary and the missing component remained
readable. The subsequent signed Group editor transaction ran against a new
temporary copy: its dry run produced one confirmation, the single execution
returned `verified` with the saved-archive postcondition and native Group
readback confirmed, and the reopened QLab inspector displayed 4.5 seconds,
4.5-second in/out fades and the Custom Curve. No cue was run.
The same dry-run/confirmation/write sequence also passed through an isolated
FastMCP client using a second temporary copy; its result was `updated` /
`verified`, with file replacement, reopen, saved postcondition and native
verification confirmed. The workspace original was then reopened unchanged.

## OSC availability and loaded MCP

QLab displayed OSC access enabled on port 53000, but its existing process did
not have a 53000 listener. After checking the only open document was unmodified
and no cues were active, QLab was restarted and the same workspace reopened.
The original file hash was unchanged. QLab then listened on TCP and UDP 53000,
and `qlab_check_connection` returned ready with Edit Mode and read access.

The older MCP process initially continued to expose the OSC setter. After the
MCP was restarted, Group details reported `saved_archive` as the transport.
Against a fresh temporary copy, the installed `qlab_edit_group_cues` dry run
returned an archive confirmation; one execution returned `updated` / `verified`.
Fresh MCP readback gave duration 2.0, and the saved archive gave offset -0.024
and both fade durations 0.024, scaled from the existing 2.4/-0.0288/0.0288
baseline. The existing effect-graph check matched before and after the write.
The original workspace was reopened and its file hash remained unchanged.
