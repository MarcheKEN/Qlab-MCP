## AGENT UX

The read-only contract was usable without guessing IDs: the overview and
query tools returned exact UUIDs, parent IDs, health, activity, and truncation
metadata. The active app did not expose wire-level `tools/list` schemas or
annotations, so protocol-level schema/annotation claims are intentionally not
made. Descriptions consistently required explicit workspace and cue UUIDs and
the readiness → dry-run → fresh token → execute once → fresh readback flow.

Observed UX strengths were exact-ID discovery, operation-specific tokens,
explicit no-retry guidance, and clear separation between structural success and
GO readiness. The main UX limitation is transport context: a client with only
the app catalog cannot inspect wire schemas or annotation flags, so those must
be verified separately with a protocol-level client.
